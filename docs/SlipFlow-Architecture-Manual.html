สถาปัตยกรรมภาพรวม (High-Level Web Application Architecture)

ออกแบบตามแนวทาง Cloud-Native Web Application Architecture โดยแยกชั้นการเชื่อมต่อของผู้ใช้ (Client & Messaging Channels), ชั้นประมวลผลที่ Edge (Application Layer), ชั้น AI OCR ตรวจสลิป และชั้นฐานข้อมูลแยกตามร้านค้า (Multi-Tenant Data Layer)

แผนภาพที่ 1: โครงสร้างการทำงานตั้งแต่ลูกค้าส่งรูปสลิป จนถึงการตรวจ AI OCR, กฎป้องกันผู้ขาย 4 ด่าน และการบันทึกลงฐานข้อมูล D1 แยกตามร้านค้า

⚡ Edge Serverless

รันบน Cloudflare Workers (Startup ~4ms) ไม่หลับ ไม่เสียเวลารอปลุกเซิร์ฟเวอร์ฝั่งรับ Webhook

🏪 Multi-Shop 100%

แยกข้อมูลทุกตารางด้วย shop_id และแยก URL Webhook เฉพาะแต่ละร้าน ไม่ปนข้อมูลกัน

🛡️ 4-Gate Verification

ตรวจทั้ง QR/CRC, สลิปซ้ำ 2 ชั้น, เลขบัญชีรับเงินของร้าน (Whitelist) และยอดขั้นต่ำ

👑 Super Admin

มีบัญชี Admin กลางสำหรับดูยอดรวมทุกร้าน สลับเข้าช่วยจัดการร้าน และรีเซ็ตรหัสผ่าน

องค์ประกอบระบบแบบ 3 ชั้น (3-Tier Web Application Layers)

เพื่อให้ดูแลรักษาง่ายและขยายระบบได้ไม่จำกัด ระบบแบ่งออกเป็น 3 ชั้นมาตรฐาน (Presentation, Application Logic, และ Data Storage)

TIER 1 · PRESENTATION LAYER

ส่วนติดต่อผู้ใช้และปลั๊กอิน

  • React 19 + TypeScript + Vite: หน้าเว็บ SPA รองรับทั้งคอมและมือถือ
  • Browser jsQR Pre-Scan: สแกน QR บนเบราว์เซอร์ทันทีเมื่อลากสลิปวาง
  • Chrome Extension (MV3): ฝังปุ่มตรวจสลิปใน chat.line.biz และ business.facebook.com
  • Smart Live Polling: ซิงค์รายการสลิปใหม่ขึ้นหน้าจอพร้อม Toast แจ้งเตือนอัตโนมัติ
TIER 2 · APPLICATION LAYER

Hono Worker & Business Logic

  • Web Crypto Security: ตรวจลายเซ็น X-Line-Signature และ X-Hub-Signature-256
  • PBKDF2-SHA256 Auth: เข้ารหัสรหัสผ่าน 100,000 รอบ พร้อม Bearer Session
  • Non-Slip Filter: ข้ามรูปสินค้าทั่วไปในแชต ไม่ส่งข้อความแจ้งเตือนรบกวนลูกค้า
  • Account Matcher: เทียบเลขบัญชีที่ถูกปิดบางหลัก (xxx-x-x5678-x) กับบัญชีร้าน
TIER 3 · DATA & STORAGE LAYER

Cloudflare D1 (SQLite APAC)

  • Relational Schema: 7 ตารางหลักพร้อม Composite Index ค้นหาความเร็วสูง
  • Strict Tenant Guard: ทุก Query บังคับกรอง WHERE shop_id = ?
  • UTF-8 BOM CSV Exporter: ส่งออกสมุดรายรับเปิดภาษาไทยใน Microsoft Excel ได้ทันที
  • Local Node Adapter: รันโค้ดชุดเดียวกันบน node:sqlite ในเครื่องได้ 100%

สถาปัตยกรรมแยกข้อมูลหลายร้านค้า (Multi-Shop Isolation & Super Admin)

ร้านค้าแต่ละร้านจะมีรหัส webhookSlug (เช่น sh_b0cd3dc3...) และ extensionApiKey ของตัวเอง ทำให้ข้อมูลสลิปและแชตบอทแยกขาดจากกันอย่างสมบูรณ์ โดยมี Super Admin ดูแลภาพรวมอยู่ชั้นบนสุด

แผนภาพที่ 2: การแยกพื้นที่ข้อมูล (Tenant Isolation) ระหว่างร้านค้าแต่ละร้าน และการกำกับดูแลจากบัญชี Super Admin
ระดับสิทธิ์ (Role) ขอบเขตการมองเห็นข้อมูล การตั้งค่า LINE / Facebook / บัญชีรับเงิน การจัดการผู้ใช้งานอื่น
ADMIN (Super Admin) ดูยอดรวมทั้งระบบ + สลับเข้าไปดูหรือแก้ได้ทุกร้านค้า ช่วยตั้งค่าให้ร้านใดก็ได้ที่สลับเข้าไปดู สร้างผู้ใช้ใหม่, รีเซ็ตรหัสผ่าน, ปรับสิทธิ์, ระงับร้าน/ผู้ใช้
SELLER (เจ้าของร้าน) เห็นเฉพาะร้านค้าที่ตนเองเป็นเจ้าของเท่านั้น (ข้ามร้านได้ 403) ตั้งค่าเฉพาะร้านของตนเอง (สร้างเพิ่มได้หลายสาขาในบัญชีเดียว) ไม่สามารถเข้าเมนู Admin หรือดูข้อมูลร้านอื่นได้

เกราะป้องกันผู้ขาย 4 ด่าน (4-Gate Seller Verification Logic)

1
ด่านที่ 1: ตรวจ QR Code มาตรฐานธนาคาร & ค่า CRC16
ถ้ารูปที่ลูกค้าส่งไม่มี QR สลิป (เช่น ส่งรูปเสื้อผ้า/สินค้าที่ต้องการซื้อ) ระบบจะจัดเป็น IGNORED_NON_SLIP และ ไม่ส่งข้อความแจ้งเตือนกวนลูกค้า แต่ถ้าเป็นสลิปที่ QR ถูกตัดต่อจน CRC เพี้ยน จะตีเป็น ไม่ผ่าน
2
ด่านที่ 2: ตรวจสลิปซ้ำ 2 ชั้น (Dual Duplicate Check)
เช็กเลขอ้างอิง (transRef) ทั้งจากประวัติของ my-slip-reader และในตาราง transactions ของร้านค้านั้นบน D1 หากเคยรับยอดไปแล้วจะตีเป็น สลิปซ้ำ และไม่บวกยอดซ้ำเด็ดขาด
3
ด่านที่ 3: เทียบบัญชีปลายทางของร้านค้า (Receiver Whitelist)
ระบบดึงตัวเลขที่มองเห็นบนสลิป (เช่น xxx-x-x5678-x หรือ 08x-xxx-9988) และชื่อบัญชีจาก OCR มาเทียบกับบัญชีที่ร้านลงทะเบียนไว้ หากโอนเข้าบัญชีคนอื่นจะตีเป็น ผิดบัญชีร้าน
4
ด่านที่ 4: ตรวจความสมบูรณ์ของยอดเงิน (Precision Amount Check)
หากสลิปเป็นของจริงแต่ภาพเบลอจน OCR อ่านยอดเงินได้ 0.00 บาท หรือต่ำกว่ายอดขั้นต่ำที่ร้านตั้งไว้ ระบบจะพักไว้ที่สถานะ รอตรวจยอด เพื่อให้ผู้ขายกรอกยอดจริงและกดอนุมัติในคลิกเดียว
จุดเด่นสำคัญ: การใช้ ctx.waitUntil() บน Cloudflare Workers ทำให้บอทตอบ HTTP 200 ให้ LINE และ Facebook ทันทีในระดับมิลลิวินาที แม้ช่วงที่ my-slip-reader.onrender.com เพิ่งตื่นจากโหมดพัก (Cold Start 20–40 วินาที) Webhook ก็จะไม่หลุดหรือ Timeout และหาก replyToken หมดอายุ ระบบจะสลับไปใช้ pushMessage อัตโนมัติ

ขั้นตอนที่ 1: สมัครเปิดร้านใหม่ / สลับสาขา

  1. เข้าเว็บ https://slipflow-seller-dashboard.xenz-wora.workers.dev
  2. เลือกแท็บ สมัครเปิดร้านใหม่ กรอกชื่อร้านค้า, Username และรหัสผ่าน

วิธีเชื่อมต่อปลั๊กอินตรวจสลิปอัตโนมัติ (LINE OA / Facebook / Chrome)

🟢 วิธีที่ 1: ต่อ LINE OA Bot (ใช้บนมือถือ 24 ชม.)

แนะนำ
  1. ใน Dashboard เปิดเมนู ปลั๊กอิน LINE / FB > แท็บ LINE OA Bot แล้วคัดลอก Webhook URL เฉพาะร้านของคุณ (.../api/line/webhook/sh_xxxx)
  2. เข้า manager.line.biz > ตั้งค่า > Messaging API (กดเปิดใช้) และที่เมนู ตั้งค่าการตอบกลับ ให้เลือกโหมด แชต + เปิด Webhook
  3. เข้า developers.line.biz เลือก Channel ของร้าน:
    • คัดลอก Channel Secret (แท็บ Basic settings)
    • กด Issue คัดลอก Channel Access Token (แท็บ Messaging API)
    • วาง Webhook URL ของร้าน กด Verify และเปิด Use webhook
  4. นำ Secret และ Token มาวางใน Dashboard แล้วกด บันทึกการตั้งค่า LINE Bot
  5. (เสริม) หากต้องการให้แจ้งเตือนเข้ากลุ่มแอดมิน เชิญบอทเข้ากลุ่มแล้วพิมพ์ !id นำรหัส C... มาใส่ช่อง Admin Target ID

🔵 วิธีที่ 2: ต่อ Facebook Page Messenger (มือถือ 24 ชม.)

Meta API
  1. เข้า developers.facebook.com > สร้างแอปประเภท Business > เพิ่มผลิตภัณฑ์ Messenger
  2. ไปที่ App Settings > Basic คัดลอก App Secret
  3. ไปที่ Messenger API Settings เชื่อมเพจร้านค้าแล้วกด Generate เพื่อคัดลอก Page Access Token
  4. เปิด Dashboard เมนู ปลั๊กอิน LINE / FB > แท็บ Facebook Messenger:
    • วาง App Secret และ Page Access Token แล้วกดบันทึกก่อน
    • คัดลอก Callback URL เฉพาะร้าน (.../api/messenger/webhook/sh_xxxx) และ Verify Token (fbv_...)
  5. นำ Callback URL และ Verify Token ไปใส่ในหน้า Configure Webhooks ของ Meta กด Verify and Save แล้วติ๊ก Subscribe ฟิลด์ messages

💻 วิธีที่ 3: Chrome Extension สำหรับแอดมินตอบแชตบนคอม (ไม่ต้องตั้งค่า Webhook)

LINE & FB Web

เหมาะสำหรับร้านที่ใช้แชตบอทเจ้าอื่นอยู่แล้ว หรือยังไม่สะดวกตั้งค่า Meta Developers โดยปลั๊กอินตัวเดียวทำงานได้ทั้งบน https://chat.line.biz และ https://business.facebook.com

  1. เปิด Chrome / Edge ไปที่ chrome://extensions > เปิดสวิตช์ Developer mode มุมขวาบน > กด Load unpacked เลือกโฟลเดอร์ line-chat-extension
  2. เปิด Dashboard เมนู ปลั๊กอิน LINE / FB > แท็บ Chrome Extension คัดลอก Dashboard Server URL และ Seller Extension API Key ของร้านไปวางในป็อปอัป Extension
ทิปการทดสอบก่อนใช้งานจริง: ในหน้า ปลั๊กอิน LINE / FB มีกล่อง ทดสอบจำลองลูกค้าส่งสลิป ทั้งของ LINE และ Facebook ให้คุณอัปโหลดรูปสลิปจริงเพื่อทดสอบการอ่านยอดและดูตัวอย่างข้อความตอบกลับได้ทันทีโดยยังไม่ต้องผูก Webhook

ความสามารถของเมนู "ดูแลระบบรวม (Admin)"

  • ดูภาพรวมทั้งแพลตฟอร์ม: ยอดโอนยืนยันรวมทุกร้านวันนี้, เดือนนี้ และจำนวนร้านค้าที่เปิดใช้งาน

  • ระงับการใช้งานชั่วคราว: เมื่อกดระงับร้านค้า ระบบจะบล็อกการรับสลิปผ่าน Webhook และ Extension ของร้านนั้นทันที

ตารางความหมายสถานะสลิปและการจัดการ (Slip Status Reference)

สถานะในระบบ นับเป็นรายรับ? สาเหตุที่เกิดสถานะนี้ วิธีจัดการของผู้ขาย
ยืนยันแล้ว (VERIFIED) นับรวมทันที QR/CRC ถูกต้อง + ไม่ซ้ำ + ตรงบัญชีร้าน + ยอดเงิน > 0 ไม่ต้องทำอะไร ระบบลงบัญชีและตอบแชตแล้ว
รอตรวจยอด (NEEDS_REVIEW) ยังไม่นับรวม QR แท้และตรงบัญชีร้าน แต่ภาพเบลอจน OCR อ่านยอดได้ 0.00 หรือต่ำกว่ายอดขั้นต่ำ คลิกที่รายการ > ดูข้อความ OCR > กรอกยอดเงินจริงแล้วกด อนุมัติเป็นรายรับ
สลิปซ้ำ (DUPLICATE) ไม่นับรวม เลขอ้างอิง (transRef) เคยถูกบันทึกในร้านนี้ไปแล้ว ตรวจสอบกับลูกค้า (คลิกดูเวลาที่เคยส่งครั้งแรกได้ในรายละเอียดรายการ)
ผิดบัญชีร้าน (WRONG_ACCOUNT) ไม่นับรวม เลขบัญชีหรือชื่อบัญชีปลายทางบนสลิปไม่ตรงกับ Whitelist ของร้าน หากเป็นบัญชีใหม่ของร้าน ให้เพิ่มเลขบัญชีในเมนูตั้งค่า แล้วกดอนุมัติรายการ
ไม่ผ่าน (INVALID) ไม่นับรวม ไม่พบ QR สลิป หรือค่า CRC ไม่ตรง (สลิปถูกตัดต่อ/ภาพไม่ชัด) แจ้งลูกค้าให้ส่งภาพสลิปต้นฉบับที่มี QR Code ชัดเจนอีกครั้ง
ยกเลิก (VOIDED) ไม่นับรวม ผู้ขายกดยกเลิกรายการเอง (เช่น คืนเงินลูกค้า/ออเดอร์ยกเลิก) สามารถเปลี่ยนสถานะกลับเป็นยืนยันแล้วได้ตลอดเวลาหากยกเลิกผิดใบ
